# Architecture Decision Records

This directory contains lightweight Architecture Decision Records (ADRs) for
every new capability added to Learning OS after v1.0.0-rc1.

## What is an ADR?

An Architecture Decision Record is a short document that captures a
significant architectural decision, along with its context and consequences.

Each ADR follows this format:

1. **Context** — Why do we need to make this decision?
2. **Decision** — What are we proposing to do?
3. **Alternatives Considered** — What other options did we evaluate?
4. **Consequences** — What becomes easier or harder as a result?

## When to Write an ADR

An ADR is required for:
- Adding a new plugin type (e.g., a new parser, embedder, or retriever)
- Changing a core interface contract
- Adding a new external dependency
- Architectural decisions that affect multiple modules
